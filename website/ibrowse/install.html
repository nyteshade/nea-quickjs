Runtime layout

Choose the library variant that matches the target machine and copy it to LIBS:quickjs.library. Put qjs somewhere on the command path, such as C: or a project-local tools drawer.

FileUse
quickjs.020soft.librarySafest baseline for 68020+ machines without requiring an FPU.
quickjs.020fpu.library68020 or better with 68881/68882-compatible FPU.
quickjs.040soft.library68040 scheduling, no FPU dependency.
quickjs.040fpu.library68040-class systems with FPU.
quickjs.060soft.library68060 scheduling, no FPU dependency.
quickjs.060fpu.libraryFast path for 68060 systems with FPU.

First commands

copy libs/quickjs.020soft.library LIBS:quickjs.library
copy c/qjs C:qjs
stack 65536
qjs -e "print(100 + 110)"
qjs examples/window_hello.js

The 64K stack is not optional for serious scripts. The bytecode interpreter uses task stack, and the CLI performs a stack check so failures are clearer.

Configuration files

PathPurpose
S:QJS-Config.txtDefault command-line flags, one per line. Useful for setting --std or local policy.
S:QJS-Startup.jsOptional JavaScript loaded before REPL or script mode. Good for personal helpers and globals.

Build from source

make lib
make cli
execute tests/run-tests.script

Development builds use VBCC/SAS-C-era constraints and the Amiga shared library ABI. The source tree records the current packed-decimal version in library/vbcc/libraryconfig.h.
