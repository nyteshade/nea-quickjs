Roadmap

What is solid, what is partial, and what comes next.

HomeInstallArchitectureAPIReactionExamplesRoadmap

Current strengths

  • Shared library architecture is established.
  • CLI, REPL, modules, std/os/bjson, and Amiga file I/O are working parts of the platform.
  • Node-style compatibility has meaningful coverage for common scripts.
  • Reaction/BOOPSI wrappers are deep enough for native GUI applications.
  • Six CPU/FPU library variants are tracked by the build.

Known partial areas

AreaReason
Full Node parityClassic AmigaOS does not have fork, V8, daemon service assumptions, or POSIX process semantics.
StreamsUseful push-mode subset exists; full backpressure is not implemented.
CryptoCommon digests work; SHA-384/SHA-512 depend on AmiSSL availability.
Networkingfetch is the priority client API; raw socket APIs are future work.

Next directions

  • Keep improving child_process and worker-backed async consumers.
  • Broaden Amiga module discovery and native plugin loading.
  • Continue Reaction wrapper hardware validation and demo coverage.
  • Harden fetch and network capability reporting across real TCP/IP stacks.
  • Prepare a clean v1 release line once the API and packaging are stable.
Roadmap reflects source docs current to April 2026.
